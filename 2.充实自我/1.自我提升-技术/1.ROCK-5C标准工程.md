## 一件换源

- ROCK-5C下有一个文件夹专门管理各种时刻使用的软件源，一键对可更换的软件源进行备份并进行换源的指令如下

```bash
# 1. 只备份所有 50- 开头的源文件（安全）
sudo mkdir -p /etc/apt/sources.list.d/backup
sudo cp /etc/apt/sources.list.d/50-* /etc/apt/sources.list.d/backup/

# 2. 替换 50-bookworm.list（主源）
sudo tee /etc/apt/sources.list.d/50-bookworm.list > /dev/null << EOF
deb https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm main contrib non-free non-free-firmware
deb-src https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm main contrib non-free non-free-firmware
EOF

# 3. 替换 50-bookworm-updates.list（更新源）
sudo tee /etc/apt/sources.list.d/50-bookworm-updates.list > /dev/null << EOF
deb https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm-updates main contrib non-free non-free-firmware
deb-src https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm-updates main contrib non-free non-free-firmware
EOF

# 4. 替换 50-bookworm-security.list（安全补丁）
sudo tee /etc/apt/sources.list.d/50-bookworm-security.list > /dev/null << EOF
deb https://mirrors.tuna.tsinghua.edu.cn/debian-security/ bookworm-security main contrib non-free non-free-firmware
deb-src https://mirrors.tuna.tsinghua.edu.cn/debian-security/ bookworm-security main contrib non-free non-free-firmware
EOF

# 5. 替换 50-bookworm-backports.list（新版软件源）
sudo tee /etc/apt/sources.list.d/50-bookworm-backports.list > /dev/null << EOF
deb https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm-backports main contrib non-free non-free-firmware
deb-src https://mirrors.tuna.tsinghua.edu.cn/debian/ bookworm-backports main contrib non-free non-free-firmware
EOF
```
- `sudo cp /etc/apt/sources.list.d/50-* /etc/apt/sources.list.d/backup/`将目录下`50-`开头的所有目标文件复制到指定目录下
- `<< EOF`会将下一行开始的输入，写进上述文件，直到`EOF`停止
- `sudo tee /etc/apt/sources.list.d/50-bookworm-backports.list > /dev/null`如果没有`> /dev/null`会将写入的内容同时输出到屏幕，加上`> /dev/null`将打印到屏幕上的内容丢进垃圾桶
- `https://mirrors.tuna.tsinghua.edu.cn/debian-security/`也就是常说的`URL`统一资源定位符，可以定位网络资源地址

- 完成上述操作，使用`sudo apt update`将列表更新到本地，从而实现后续搜索定位需要下载的资源的最新地址

## SoC、板卡、BSP

- **ROCK 5C 有 NPU；你在板卡手册上没看到，是因为NPU 属于 SoC（RK3588S2）特性，不在板卡用户手册里详述；AI 推理靠瑞芯微 RKNN 工具链 + RKNPU 驱动 + RKNN-Lite 运行时调用 NPU 硬件加速。**
- ROCK 5C：RK3588S2，**6 TOPS（INT8）** NPU，支持 INT4/INT8/INT16/FP16/BF16/TF32


- SoC芯片：整颗芯片塞进 CPU、GPU、NPU、各类外设控制器
- 也就是口语常说的“芯片”

- **板卡**：PCB 电路板，**焊满元件的整块板子**，板卡厂商提供，或者公司自研


- **BSP = 让系统跑在这块板子上的 “底层软件包”**，全称 **Board Support Package**

1. **Bootloader（引导程序）**
    
    - 如 U‑Boot：初始化 DDR、串口、Flash，加载内核。
2. **CPU/SoC 底层初始化代码**
    
    - 时钟、PLL、电源域、中断、MMU 配置。
3. **设备树（Device Tree）**
    
    - 用文本描述板上硬件：SoC 外设、引脚分配、内存、Flash、网卡等。
4. **板级驱动**
    
    - UART、I2C、SPI、GPIO、以太网、USB、LCD、Touch、SD 卡等驱动。
5. **内核配置与补丁**
    
    - 针对该 SoC / 板的内核 defconfig、驱动适配、bug 补丁。


- 通常由 **SoC 厂商**（如瑞芯微、全志）提供参考 BSP。
- 然后 **板卡厂商 / 产品公司** 再根据自己板子修改、适配。

## NPU

- INT8、INT16这些精度，就是 AI 模型里**权重、特征、像素、梯度**这类运算数据的存储格式，直接对应计算行为

- TOPS(**Tera Operations Per Second**),每秒万亿次运算，**AI 算力单位**
- 位数越小：速度越快、功耗越低、精度越低

- `ext4`：Linux 目前**主流默认日志型文件系统**，用于系统盘、数据盘
- `vfat`：全称 **FAT32**（Linux 下统一标注为 vfat），Windows / EFI 标准文件系统；EFI 固件**强制要求**引导分区使用 FAT32，所以 Linux + UEFI 启动环境，`/boot/efi` 固定是 vfat；
- `fuse.vmhgfs-fuse`:基于 **FUSE（用户态文件系统）** 实现的 **VMware 共享文件夹文件系统**。
- `iso9660`：无作用，可以直接卸载
- `tmpfs`：将内存资源封装为文件的硬件资源

#### git submodule 子模块：

单纯解压丢文件夹会缺少 `.git` 版本记录，git 识别不出子模块，执行 `git submodule status` 会报错、更新失败。
1. 对应子仓库单独下载完整 zip；
2. 解压到项目指定子模块路径；
3. 执行：
```bash
# 让 git 重新绑定子模块版本记录。
git submodule sync
git submodule update --init
```

- 以上操作并不完善，git子模块最好不要使用这种方法
#### 包管理器托管依赖（apt、conda、npm 包）

- 替换软件源，确保对应的包管理工具唯一指定清华源

#### CMake FetchContent / Meson 构建工具拉取的 Git 依赖

这类是编译阶段才下载第三方代码，**不属于 git 子模块**，项目没有 `.gitmodules`，主仓库完全不管理第三方的 git 版本，只是构建脚本里写死仓库地址 + tag/commit。

```cmake
FetchContent_Declare(
  opencv
  GIT_REPOSITORY https://github.com/opencv/opencv.git
  GIT_TAG 4.8.0
)
FetchContent_MakeAvailable(opencv)
```
1. Windows 下载 opencv 4.8.0 对应源码压缩包；
2. 解压到 CMake 指定的存放目录（一般是 `_deps/opencv-src`）；
3. 修改 CMakeLists，注释掉 FetchContent 在线拉取代码；
4. 直接编译，构建系统只会读取文件，不校验 git 信息。

- 优点：操作简单，不用管.git，只要目录、文件完整就能编译；
- 缺点：升级版本需要手动重新下载对应源码，无法一键更新。

## 软件源仓库以及加密验证的本质

### 公钥的获取

1. Rock5C 官方系统镜像里，已经预先把 Radxa 仓库的 GPG 公钥放在 `/usr/share/keyrings/radxa-archive-keyring.gpg`
2. 公钥地址：`radxa.com` 官网 / 独立 github 密钥仓库（两者域名完全隔离，就算软件源镜像被劫持，官网域名不受影响，你可以单独下载公钥导入本地）
3. GPG 全球公钥服务器网络（[keyserver.ubuntu.com](https://link.wtturl.cn/?target=https%3A%2F%2Fkeyserver.ubuntu.com&scene=im&aid=582478&lang=zh "autolink")、pgp.mit.edu），开发者上传公钥后，全网多节点同步备份（可以执行命令从独立密钥服务器拉取公钥指纹）---辅助验证
```bash
gpg --keyserver keyserver.ubuntu.com --recv-keys RADXA公钥ID
```

### **完整验证流程：**
#### 1. 公钥信任建立（一次性操作，和镜像无关）

1. 原厂（Radxa）离线保管**签名私钥**，对外公开配套公钥，并在官网公示公钥唯一指纹；
2. 用户获取原厂公钥（三种安全渠道，优先级从高到低）：
    
    - 渠道 1（最安全）：官方系统镜像预装公钥，存于本地 `/usr/share/keyrings/`，无需联网；
    - 渠道 2：从厂商独立官网 / 独立 GitHub 仓库下载公钥；
    - 渠道 3（辅助交叉验证）：联网全球 GPG 密钥服务器拉取公钥，对比指纹确认和官网一致；
    
3. 软件源配置绑定本地公钥文件 `[signed-by=xxx.gpg]`，指定只用该公钥校验仓库，不采信网络临时密钥。

#### 2. apt update 阶段：GPG 签名校验（第一道安全锁，镜像无法篡改）

1. apt 从国内镜像 / 上游 GitHub 下载仓库核心文件：`Release`（全仓库包哈希清单）+ `Release.gpg`（原厂私钥生成的签名）；
2. 使用本地提前存放的**原厂公钥**解密验证签名：
    
    - 校验通过：证明这份软件清单是原厂私钥签发，镜像 / 中间人没有篡改清单；
    - 校验失败：直接丢弃该仓库所有索引，拒绝使用此源；
    
3. 镜像仅原样同步文件，无原厂私钥，无法伪造合法签名，篡改任何内容都会校验失败。

#### 3. apt install 阶段：哈希完整性校验（第二道安全锁）

1. 依据合法的`Release`清单，下载对应`.deb`软件包；
2. 本地计算下载完成 deb 包的 SHA256 哈希，和`Release`清单内官方记录的哈希比对；
3. 哈希不一致判定文件损坏 / 被篡改，直接删除包、终止安装。

### 文件作用

#### 1. bin -> usr/bin
- 英文全称：Binary
- 说明：软链接指向 `/usr/bin`，存放全体用户可用的基础二进制可执行命令（ls、cp、cat、python 等），现代系统统一将普通程序归集到 usr/bin，根目录仅做兼容链接。

#### 2. boot
- 英文全称：Bootstrap
- 说明：系统启动引导目录，存放内核镜像 Image、设备树 dtb、U-Boot 启动配置；修改板载屏幕、摄像头硬件驱动都需要操作此目录文件。

#### 3. config
- 英文全称：Configfs（Configuration File System）
- 说明：嵌入式Linux特有虚拟文件系统，用于动态配置底层硬件（GPIO、I2C、PWM、MIPI摄像头、背光等），PC端通用Linux无此目录；1970时间戳为虚拟文件系统正常特征。

#### 4. dev
- 英文全称：Device
- 说明：硬件设备文件目录，所有外设映射为文件（/dev/video0摄像头、/dev/mmcblk存储、/dev/dma_heap NPU硬件节点），开机自动生成，重启清空。

#### 5. etc
- 英文全称：Editable Text Configuration
- 说明：全系统配置文件总目录，永久存储；包含软件源、环境变量、开机自启服务、设备权限规则、磁盘挂载配置等，系统所有静态配置均在此。

#### 6. home
- 英文全称：Home Directory
- 说明：普通用户专属家目录，`/home/radxa` 为当前登录用户工作区，存放代码、AI模型、数据集、自定义脚本；root用户不存放在此。

#### 7. lib -> usr/lib
- 英文全称：Library
- 说明：软链接指向 `/usr/lib`，系统共享库 `.so` 文件存放目录，程序运行依赖的C/C++库、OpenCV、RKNN动态库、内核模块均在此。

#### 8. lost+found
- 英文全称：Lost and Found
- 说明：文件系统修复目录，异常断电、存储损坏后丢失的文件碎片会暂存此处，嵌入式频繁掉电容易产生碎片，可定期清理。

#### 9. media
- 英文全称：Media Devices
- 说明：可移动媒体自动挂载目录，插入U盘、TF卡、移动硬盘后系统自动挂载至此，用于临时拷贝模型、素材文件。

#### 10. mnt
- 英文全称：Mount
- 说明：手动临时挂载目录，开发调试使用，可手动挂载磁盘分区、NFS网络共享文件夹，常用于PC与开发板互传工程代码。

#### 11. opt
- 英文全称：Optional Application Software
- 说明：独立大型第三方软件安装目录，完整SDK、交叉编译工具链、原厂RKNN-Toolkit2等整套大型程序推荐安装在此。

#### 12. proc
- 英文全称：Process File System
- 说明：内核虚拟进程文件系统，完全驻留内存、断电消失；查看CPU、内存、驱动模块、网络、进程实时状态（cat /proc/cpuinfo 等）。

#### 13. root
- 英文全称：Root User Home
- 说明：超级管理员root用户专属家目录，拥有系统最高读写权限，存放底层内核编译、系统级调试脚本，普通radxa用户无写入权限。

#### 14. run
- 英文全称：Runtime
- 说明：运行时临时目录，基于tmpfs内存文件系统，重启清空；存放进程PID文件、程序通信socket、服务临时缓存数据。

#### 15. sbin -> usr/sbin
- 英文全称：System Binary
- 说明：软链接指向 `/usr/sbin`，管理员专属系统命令（fdisk、mount、网络配置、系统服务管理），普通用户无完整执行权限。

#### 16. srv
- 英文全称：Service
- 说明：系统网络服务数据目录，存放FTP、HTTP等服务资源文件，嵌入式AI开发极少使用。

#### 17. sys
- 英文全称：System File System
- 说明：底层内核硬件虚拟文件系统，比config更底层；操作总线、寄存器、网口、PWM、NPU功耗频率、硬件电源管理节点。

#### 18. tmp
- 英文全称：Temporary
- 说明：全局公共临时文件夹，所有用户读写权限，存放编译缓存、临时解压文件、临时图片素材；系统定时清理，重启全部清空。

#### 19. usr
- 英文全称：Unix System Resource
- 说明：系统软件资源主目录，现代Linux核心目录，拆分：
- /usr/bin 普通程序、/usr/sbin管理程序、/usr/lib库文件、/usr/share示例文档、/usr/local手动编译软件。

#### 20. var
- 英文全称：Variable
- 说明：可变数据目录，程序运行持续写入数据；包含系统日志、apt软件包缓存、数据库、软件运行状态缓存、持久化临时文件。
