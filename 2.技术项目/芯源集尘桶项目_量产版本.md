###### 输出字符串的实现

```c
// 手写极简版 
printf int my_printf(const char *fmt, ...) 
{ 
	int count = 0; // 循环：逐个读取字符串里的字符 
	while(*fmt != '\0') // 没到字符串结尾就一直循环 
	{ 
		char c = *fmt; // 取出当前字符 // 【核心】调用 fputc 发送单个字符 
		fputc(c, stdout); count++; // 统计字符数 fmt++; // 指针后移，取下一个字符 
	} 
	return count; // 返回总字符数 
}
```

stdout 只是一个地址固定的空指针或无效指针，它不指向任何硬件，也不指向串口。
###### 寻址单位

1. 绝大多数处理器（MCU、32/64 位 CPU），**最小寻址单位都是 1 字节（8 bit）**，地址直接对应字节，**位没有独立地址**
2. **整个结构体共用**同一个**起始内存地址**，结构体的所有成员都从这个地址开始，按顺序依次往后排列，**没有给每个成员单独分配独立的首地址**




###### size_t 与 int

- 本质区别：int = 通用有符号整数；size_t = 专门表示大小/数量的无符号整数，大小与平台指针位宽匹配。
- 使用习惯：凡是长度/大小/索引用 size_t，需要负数或一般整数逻辑用 int

###### 编译链接以及头文件和源文件的关系

编译单位是单个 .c 文件。编译器一次只看一个 .c 文件，以及它 `#include` 进来的所有头文件。编译器只做语法检查，然后生成目标文件（.o/.obj）。它不关心函数到底有没有实现，只关心调用的函数有没有声明（原型对不对），以及类型、参数个数、返回值是否匹配。只要声明存在且对得上，编译就不会报错。

声明和定义可以完全分开。声明的作用是告诉编译器"有这个函数，长这样"，一般放在 .h 文件里。定义是函数真正的代码体，可以放在任意一个 .c 文件里。声明和定义不需要在同一个文件，甚至文件名可以毫无关系。比如在 a.h 声明，在 b.c 定义，完全合法。只要函数名、返回值、参数列表一致，就是同一个函数。

链接阶段才去找实现。每个 .c 编译成 .o 之后，链接器把所有 .o、.a、.lib、.so 捆在一起。它做的事只有一件：在所有二进制文件里，查找所有被调用函数的实现地址。找到就填上地址，生成可执行文件；找不到就报 undefined reference 或 unresolved external symbol。

一句话终极总结：编译看声明，只认原型；链接找定义，搜遍所有目标文件。声明和定义可以天各一方，只要签名一致，最后链接能对上就行。

###### 远端仓库与本地仓库没有同一个历史提交版本

```bash
1.从远端 origin 抓取最新的提交与分支引用（如 origin/main），不改动你当前工作区与本地分支
git fetch origin
2.把远端的 main 分支合并进你当前所在分支（通常应先切到本地 main 再合并）,--allow-unrelated-histories 允许合并两条没有共同祖先的历史
git merge origin/main --allow-unrelated-histories
3.解决冲突 -> git add <文件>
4.git commit
5.git push -u origin main
```
